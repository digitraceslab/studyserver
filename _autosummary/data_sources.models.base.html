data_sources.models.base¶

DataSource base model: the base class every data source type extends.

DataSource is a polymorphic model; each row belongs to one participant Profile. Querying DataSource.objects returns base rows; call get_real_instance() to get the concrete subclass before calling the hooks below.

Writing a subclass:

  • Set SOURCE_TYPE (a unique slug). Defining the subclass registers it for get_class_for_type. A form registered with @datasourceform (or FORM_CLASS) is needed for participants to add it.

  • Implement get_data_types, fetch_data and count_rows.

  • Optionally override the setup / confirmation / dashboard hooks (requires_setup, requires_confirmation, get_setup_url, confirm, get_instructions_card, show_links, revoke_before_delete, _process_data) and the deletion hooks (supports_deletion, latest_timestamp, mark_deletable, unmark_deletable).

Rows returned by fetch_data are dicts. Every source includes an int timestamp field in Unix milliseconds; the other field names depend on the source type and data type.

Access control is not part of this model: methods do not check who calls them. Views must restrict access themselves (normally to the owner profile).
