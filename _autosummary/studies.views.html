studies.views¶

Study views: public pages, participant join/consent flow and researcher data API.

All routes are mounted under /studies/ and act on the deployment’s single study (Study.objects.first()); when no study exists, the participant views raise 404 and the API views return 404 {"error": "No study configured"}.

Access groups: - Public, no login: study_detail, terms_of_service,

privacy_statement, info_sheet and their *_version views.

  • Login required (login_required; anonymous users are redirected to the login page with next): join_study, withdraw_from_study, consent_workflow, revoke_consent. They need request.user.profile.

  • Researcher API (api/...): authenticated by DRF token (Authorization: Token <key>) or session. A superuser, or a user whose profile is in Study.researchers, may call them; other authenticated users get 403 {"error": "Unauthorized"}; unauthenticated requests get DRF’s 401 {"detail": ...}; a wrong HTTP method gets 405. Session-auth POSTs need a CSRF token. Each API route also answers with a trailing slash.

The researcher API for researcher-written study page HTML is {% include join_or_login_section %} only; see the studies_tags module docstring.

Data types in the API are namespaced as <source_type>:<data_type> (e.g. aware:battery). Participants are identified only by StudyParticipant.pseudo_id (participant_id). The API only sees consents that are complete, unrevoked and linked to an active data source, and only the data types the consent allows.
